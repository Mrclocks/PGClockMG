# PGClockMG

🧰 Мастер restore и миграции + панель бэкапа PasarGuard

</div>

---

## ✨ Обзор

PGClockMG — это **два сервиса** рядом:

| Сервис | Порт по умолчанию | Назначение |
|--------|-------------------|------------|
| 🧭 **Мастер** (`pg-migrator`) | `7000` | Restore бэкапов и миграция в PasarGuard |
| 💾 **Панель бэкапа** (`pg-backup`) | `7001` | Полные бэкапы, Telegram, расписание, stream → restore |

Один запуск `install.sh` ставит оба. **Отдельного пункта меню** для бэкапа нет — установщик только спрашивает порт каждого сервиса.

> 📌 Инструмент не устанавливает PasarGuard за вас. Сначала поставьте панель, затем вернитесь.

---

## 📦 Требования

- Ubuntu 22.04+
- доступ `root`
- Docker
- PasarGuard уже установлен (для бэкапа и restore)

| URL | Примечание |
|-----|------------|
| `http://SERVER_IP:7000/?token=...` | Мастер — **токен доступа** |
| `http://SERVER_IP:7001/` | Панель бэкапа — **сильный пароль** при первом входе |

Восстановление токена мастера:

```bash
cat /opt/pg-migrator/.access_token
```

## 📥 Установка

```bash
sudo bash -c "$(curl -fsSL 'https://raw.githubusercontent.com/Mrclocks/PGClockMG/main/install.sh?v='$(date +%s))"
```

После запуска скрипт очищает экран и показывает главное меню.

### 🗂️ Меню скрипта

| Пункт | Что делает |
|-------|------------|
| 1 · Install / update | Спрашивает порт мастера (`7000`) и порт бэкапа (`7001`), ставит/обновляет оба сервиса, печатает URL |
| 2 · Uninstall | Удаляет сервисы и `/opt/pg-migrator`, предлагая сохранить бэкапы. PasarGuard не трогает |
| 3 · Redirect server | Статус, перезапуск и логи `pg-redirect` — только 3x-ui / Hiddify |
| 4 · Exit | Выход из меню |

### Режим без вопросов

```bash
sudo PG_MIGRATOR_PORT=7000 PG_BACKUP_PORT=7001 bash -c "$(curl -fsSL 'https://raw.githubusercontent.com/Mrclocks/PGClockMG/main/install.sh?v='$(date +%s))"
```

`PG_MIGRATOR_ACTION`: `install` · `uninstall` · `redirect-restart` · `menu`  
`PG_MIGRATOR_YES=1` подтверждает все вопросы автоматически.

## 🧭 Гайд по мастеру (restore и миграция)

Порт по умолчанию: **`7000`** · Вход по URL с токеном из установщика.

### Возможности

- ✅ Restore бэкапов PasarGuard — включая смену СУБД (SQLite / PostgreSQL / TimescaleDB / MySQL / MariaDB)
- ✅ Автоматическое устранение несоответствия версий TimescaleDB
- ✅ Карточка с информацией о БД после загрузки бэкапа
- ✅ Опция отключения узлов после восстановления
- ✅ Миграция с Marzban, 3x-ui, Hiddify и Remnawave
- ✅ Приём stream-бэкапа с исходного сервера и restore после **ручного подтверждения**
- ✅ Статус панели и официальные шаги установки

### Шаги restore / миграции

1. Сделайте бэкап текущей панели (или через панель бэкапа PGClockMG).  
2. Установите PasarGuard с нужной БД на **новом сервере**.  
3. Проверьте новую панель, затем временно отключите старую.  
4. Установите PGClockMG и откройте URL мастера (с токеном).  
5. Выполните restore или миграцию по шагам.

### Рекомендуемый порядок

1. 📦 Бэкап старой панели  
2. 🛠️ Установка и проверка PasarGuard на новом сервере  
3. ⏸️ Временная остановка старой панели  
4. 🚀 Restore/миграция через мастер

### Поддержка панелей (миграция)

| Панель | Статус |
|--------|--------|
| Marzban | Полная ✅ |
| PasarGuard | Restore / смена БД (не в миграции панелей) |
| 3X-UI | Полная ✅ |
| Hiddify | Частично (пользователи + redirect ссылок) |
| Remnawave | Скоро |

## 💾 Гайд по панели бэкапа

Порт по умолчанию: **`7001`** · При первом входе задайте **сильный пароль** (12+ символов, верхний/нижний регистр, цифра, спецсимвол).

### Возможности

- 📦 **Полный бандл** с официальных путей PasarGuard  
  (`/opt/pasarguard` + `/var/lib/pasarguard`) — совместим с restore мастера
- 🗄️ SQLite / PostgreSQL / TimescaleDB / MySQL / MariaDB
- 📊 Дашборд: здоровье сервера, диск бэкапов, живая статистика панели, последний бэкап
- ⏰ Ежедневное расписание (UTC) + хранение последних N архивов
- 📱 Опциональная отправка в **Telegram** (один файл на диске; дробление только для больших загрузок)
- 🔌 HTTP/SOCKS-прокси для Telegram + тег статуса **Подключено / Нет связи**
- 🌊 **Stream** бэкапа на мастер назначения → анализ → **ручное подтверждение** → restore
- 🔐 Отдельный пароль и сессия; свой порт, независимый от мастера

### Как пользоваться

1. После установки откройте `http://SERVER_IP:7001/`.  
2. Создайте / введите пароль панели бэкапа.  
3. На дашборде нажмите «Создать полный бэкап» или включите расписание в настройках.  
4. При необходимости настройте Telegram + прокси и проверьте соединение.  
5. Для переноса: на мастере назначения включите приём stream, вставьте токен в панель бэкапа источника, запустите stream — restore только после ручного подтверждения.

### Заметки по бэкапу

- Архивы: `/opt/pg-migrator/backups`
- Настройки панели: `/opt/pg-migrator/backup_panel/`
- Пароль панели бэкапа не совпадает с токеном мастера

## ⚠️ Важные заметки

### Вход в мастер (токен доступа)

Без токена мастер не открывается. Используйте URL установщика. Если ссылка потеряна:

```bash
cat /opt/pg-migrator/.access_token
```

Права файла токена: `0600` — не публикуйте его в чатах и скриншотах.

### После миграции 3x-ui / Hiddify не работают старые ссылки?

`pg-redirect` должен занять порт старой панели. Если она ещё запущена: пункт `3` (Redirect server), затем `2` (Force restart).

## 🛠️ Полезные команды

```bash
# Мастер
systemctl status pg-migrator
systemctl restart pg-migrator
journalctl -u pg-migrator -f

# Панель бэкапа
systemctl status pg-backup
systemctl restart pg-backup
journalctl -u pg-backup -f
# или файл лога:
tail -f /opt/pg-migrator/logs/backup-service.log

# Обновление обоих
sudo bash -c "$(curl -fsSL 'https://raw.githubusercontent.com/Mrclocks/PGClockMG/main/install.sh?v='$(date +%s))"

# Остановка
systemctl stop pg-migrator pg-backup
systemctl disable pg-migrator pg-backup
```

Точка отката до `v4.0.0`: тег `restore-point-pre-v4.0.0`
